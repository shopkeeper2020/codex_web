# i18n 架构规划

更新时间：2026-05-31

本文记录 `codex_web` 的国际化方向。当前已把 i18n 作为正式架构边界纳入 monorepo，并先迁移顶栏、真实右侧栏标签入口等稳定 shell 文案；后续继续扩张设置页、真实右侧栏、侧边聊天和复杂消息块前，应继续把核心 UI 文案迁入 i18n 层。

## 目标

- 第一版至少支持 `zh-CN` 和 `en-US`。
- 默认语言为 `zh-CN`。
- 设置页提供语言选项：跟随系统、简体中文、English。
- 用户可见文案不能长期散落在 React 组件、domain normalizer 或后端错误字符串里。
- 中英文都要纳入 UI 回归，避免英文更长导致按钮、菜单、Composer、右侧栏和移动端布局溢出。

## 推荐技术栈

采用：

```text
i18next
react-i18next
Intl.DateTimeFormat / Intl.RelativeTimeFormat / Intl.NumberFormat
```

原因：

- React 生态成熟。
- 支持运行时切换语言。
- JSON 资源易维护、易审查。
- 适合当前 monorepo 的 Web UI 和共享 key 类型。

## 当前目录

已新增：

```text
packages/
  i18n/
    src/
      locales/
        zh-CN.json
        en-US.json
      index.ts
      keys.ts

apps/
  web/
    src/
      i18n/
        provider.tsx
        useI18n.ts
```

`packages/i18n` 负责共享语言包、key 类型和基础 formatter 约定；`apps/web/src/i18n` 负责 React provider、语言切换、设置持久化和浏览器系统语言检测。

当前第一批迁移范围：

- 顶栏本地环境菜单、置顶摘要、底部命令行、真实右侧栏开关。
- 移动端顶栏更多菜单中的常用操作。
- 真实右侧栏标签启动器、标签栏和占位入口名称。

下一批迁移应优先覆盖左侧栏、Composer、设置页主菜单和消息块状态文案。

## 架构原则

1. 前端组件不直接写用户可见文案。

```tsx
// 不推荐
<button>新对话</button>

// 推荐
<button>{t("sidebar.newChat")}</button>
```

2. 后端 API 不返回直接展示的中文/英文句子。

后端尽量返回结构化 code 和 params：

```json
{
  "code": "DESKTOP_NOT_CONNECTED",
  "params": {}
}
```

前端再映射到：

```json
{
  "desktop.notConnected": "Codex Desktop 未连接"
}
```

```json
{
  "desktop.notConnected": "Codex Desktop is not connected"
}
```

3. `packages/domain` 不放语言文案。

domain 层只输出结构化状态：

```ts
status: "completed"
```

前端显示时再翻译：

```tsx
t("status.completed")
```

4. 日期、时间、数字走 `Intl`。

例如“1 天前 / 3 hours ago”、文件大小、计数、持续时间都应统一通过 formatter，而不是在组件里拼接字符串。

5. UI 几何要为中英文长度差异预留空间。

尤其是：

- 左侧栏 project/thread 行。
- 顶栏按钮和弹出菜单。
- 置顶摘要和真实右侧栏。
- Composer 模型/思考深度/权限/模式控件。
- 移动端底部 Composer 和抽屉菜单。

## 分阶段计划

### Phase 1：骨架与规范

- 已新增 `packages/i18n`。
- 已新增 `apps/web/src/i18n` provider。
- 语言设置先持久化在 Web 本地设置中；后续再决定是否同步到后端配置。
- 已新增 `docs/i18n.md` 并在 MVP 看板、产品规格、UI 高保真基准中引用。

### Phase 2：核心 UI 文案

优先迁移：

- 左侧栏、项目列表、会话列表、归档入口。
- 顶栏、置顶摘要、真实右侧栏入口。
- Composer 普通状态和 active turn 状态。
- 设置页主菜单和 Settings / Diagnostics。

### Phase 3：消息块状态

迁移：

- 正在思考 / 已思考。
- 正在运行 / 已运行。
- 正在编辑 / 已编辑。
- 上下文已自动压缩。
- 审批、错误、附件、文件变更、未知内容 fallback。

### Phase 4：错误与诊断

- 后端用户可见错误逐步从 message 字符串迁移到 `code + params`。
- 前端统一把 known error code 映射为本地化文案。
- 开发者诊断和原始日志可暂时保留英文/结构化内容，但普通用户态提示必须走 i18n。

### Phase 5：双语回归

- Playwright 增加 `zh-CN` 与 `en-US` 视口覆盖。
- `desktop-chromium` 和 `mobile-chromium` 都至少覆盖 shell、Composer、Settings、消息块全类型、真实右侧栏。
- 英文截图回归重点检查横向溢出、按钮截断、菜单遮挡和移动端换行。

## 优先级判断

i18n 不高于 P0 三端同步安全性，也不应阻塞当前已在推进的消息块/右侧栏结构修复；但它应进入 P1 架构收口，排在大规模新增 UI surface 之前或与其同步。

建议顺序：

1. 继续保证三端同步、active stream 和 owner/follower 安全。
2. 收当前 Desktop 高保真缺口：消息块、Composer、置顶摘要、真实右侧栏骨架。
3. 在真实右侧栏和侧边聊天继续铺开前，继续扩大已落地的 i18n package/provider 覆盖面，优先迁移核心 shell 文案。
4. 后续每新增用户可见 UI，都必须同步新增 `zh-CN` / `en-US` key。
